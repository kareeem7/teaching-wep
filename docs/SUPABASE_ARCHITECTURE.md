# بنية Supabase — SUPABASE_ARCHITECTURE

**الحالة:** تصميم للمرحلتين ٠٢ وما بعدها · **آخر تحديث:** 2026-11-04
**لا يوجد مشروع Supabase مُنشأ لهذا العمل، ولا `migrations` في هذه المرحلة.**

## ١) الشكل العام

```text
متصفح (HTML + Bootstrap 5 RTL + ES Modules)
   │  publishable/anon key فقط
   ├──► PostgREST (public)  ── RLS إلزامية على كل جدول مكشوف
   ├──► Auth (دخول، جلسات)
   ├──► Storage (صور الدروس فقط، دلو خاص)
   └──► Edge Functions (الأفعال الحساسة + منطق غير قابل للثقة بالعميل)
             │
        PostgreSQL: auth (يديره Supabase) · public (واجهة) · app (منطق، غير مكشوف)
```

**لا يوجد خادم تطبيق تقليدي، ولا Redis، ولا عامل خارجي.** ما يحتاج تعاملًا خادميًا يُنفَّذ كدالة Edge أو دالة RPC ذرية.

## ٢) المخططات والحدود

| المخطط | مكشوف للـAPI؟ | المحتوى |
|---|---|---|
| `public` | نعم | جداول يقرأها المتصفح تحت RLS (طلاب، مجموعات، حضور، دروس، أسئلة، نتائج) |
| `app` | **لا** | عضويات، صلاحيات مساعدين، دعوات، محاولات، أحداث، تدقيق، دوال مساعدة |
| `auth` | نقاط Auth فقط | مستخدمون وجلسات |
| `storage` | حسب الدلو | صور الدروس |
| `extensions` | لا | `pgcrypto`, `citext`, `pg_trgm` |

قاعدة: أي جدول يحتاج قراءة من المتصفح ⇒ `public` + RLS. أي جدول لا يحتاج ⇒ `app` ويُقرأ فقط عبر دالة.

## ٣) نمط RLS المعتمد (R-11)

```text
العضوية هي مصدر الحقيقة، لا معرّف يرسله العميل.

دالة مساعدة (STABLE, SECURITY DEFINER, search_path ثابت):
  app.current_teacher_ids() → مجموعة معرّفات المدرسين الذي ينتمي لهم المستخدم النشط
  app.has_permission(teacher_id, action) → bool (+ نطاق مجموعات)
  app.is_super_admin() → bool (قراءة فقط)
  app.can_access_group(group_id) → bool

سياسة نموذجية على students:
  SELECT USING (teacher_id IN (SELECT app.current_teacher_ids()))
  INSERT/UPDATE USING (teacher_id IN (...) AND app.has_permission(teacher_id,'students.write'))
```

**قواعد ملزمة:**
1. كل دالة `SECURITY DEFINER` تثبت `search_path` صراحةً (مثال: `search_path = app, public`).
2. `authenticated` لا يُمنح أي صلاحية مباشرة على جداول `app`.
3. `anon` لا يقرأ شيئًا من الجداول الأكاديمية؛ فقط صفحات عامة محدودة (إن وُجدت في مرحلة ٠١).
4. لا سياسة `USING (true)` — تُرفض في المراجعة.
5. كل جدول جديد في `public` يأتي مع: RLS مفعّل + سياسات + اختبار عزل (TEST_PLAN §٤).

## ٤) الدوال (Edge Functions)

| الدالة | المرحلة | الوظيفة | ملاحظات |
|---|---|---|---|
| `auth-login` | ٠٢ | دخول موحّد بحدّ معدل وتدقيق | لا يعيد تفاصيل الفشل |
| `auth-recovery` | ٠٢ | إصدار/استهلاك رابط استعادة | مرة واحدة، ٣٠ دقيقة |
| `invite-accept` | ٠٣ | قبول دعوة مدرس/مساعد | idempotent |
| `student-link` | ٠٤ | إصدار رابط ربط وقبوله | لا ربط تلقائي |
| `attendance-save` | ٠٥ | حفظ كشف حضور ذرّي | يقبل التعديل مع سبب |
| `exam-start` | ٠٨ | بدء محاولة + سحب + لقطة | يمنع محاولتين نشطتين |
| `exam-save-answer` | ٠٨ | حفظ إجابة idempotent | يقبل `client_seq` لمنع الترتيب المقلوب |
| `exam-submit` | ٠٨ | تسليم + تصحيح | ذرّي، آمن من التكرار |
| `exam-report-event` | ٠٩ | تسجيل أحداث التركيز | مؤشرات لا اتهام |
| `results-release` | ٠٩ | نشر/حجب نتيجة | بسبب مسجل |
| `export-csv` | ١٠ | تصدير نطاق محدد | يحمي من CSV Injection |
| `notify-broadcast` | ١١ | تنبيه داخلي | يحدد المستلمين على الخادم |

كل دالة: تتحقق من JWT، ثم الصلاحية، ثم تُسجّل في `app.audit_log` عند اللزوم، وتُرجع أخطاء بنمط `{code, message_ar}` بلا تفاصيل داخلية.

## ٦) الملفات والمهاجرات

```text
supabase/
├── config.toml
├── migrations/
│   ├── 0001_extensions.sql
│   ├── 0002_profiles_and_memberships.sql
│   ├── … مرقمة تسلسليًا، اسم واضح، بلا تعديل بعد الدفع
│   └── (اسم بادئة/لاحقة لا يُعاد ترتيبها بعد التطبيق — درس سابق)
└── functions/
    ├── _shared/ (auth.ts, rate-limit.ts, audit.ts, errors.ts)
    └── <function>/index.ts
```

**قواعد المهاجرات:**
1. مهاجرة واحدة = تغيير منطقي واحد، وقابلة للإعادة على قاعدة فارغة.
2. لا تحذف جدولًا/عمودًا في نفس المهاجرة التي تُوقف استخدامه.
3. كل مهاجرة تُختبر على قاعدة محلية فارغة قبل الدفع.
4. `supabase db diff` ليس بديلًا عن مراجعة بشرية.

## ٩) الأسرار والمفاتيح

| المفتاح | مكانه | من يراه |
|---|---|---|
| publishable/anon | المتصفح | عام بالتصميم، ومحمي بـRLS |
| `service_role` / secret | بيئة الدوال والمهاجرات فقط | **لا المتصفح، لا المستودع، لا السجلات** |
| مفاتيح التخزين الاحتياطي | مدير أسرار خارجي | العميل فقط |

ممنوع في `public/` أو أي ملف يُدفع: أي سر، أو `.env` حقيقي. يُستخدم `.env.example` بأسماء فقط.

## ١٠) الملاحظة والتشغيل

- **ملاحظة أخطاء:** تسجيل أخطاء الدوال في جدول `app.error_log` (بلا بيانات شخصية)، ولوحة Supabase للمشروع.
- **صحة:** نقطة `/healthz` خفيفة، وفحص دوري من خارج المنصة (مجاني مثل UptimeRobot أو بديل).
- **النسخ الاحتياطي:** خطة Supabase للمشروع تحدد مدة الاحتفاظ. **إن لم تكن كافية، نسخة منطقية يومية إلى تخزين خارجي شرط إطلاق.**
- **أهداف الاستعادة (R-16، تنتظر اعتمادًا):** `RPO ≤ ٢٤ ساعة` و`RTO ≤ ٨ ساعات`، مع **تمرين استعادة فعلي موثق** قبل الإطلاق — لا يُقبل «نسخة احتياطية موجودة» بلا استعادة مجرّبة.
- **بيئتان:** تطوير وإنتاج منفصلتان. لا اختبار على بيانات حقيقية.

## ٤. السبب الجذري الأكبر، بشرح تقني

```yaml
# قبل
- name: نشر الدوال الست على بيئة الاختبار
  if: ${{ inputs.deploy_functions != false }}
```

في حدث `workflow_dispatch` تكون `inputs.deploy_functions` = `true` ⇒ تعمل.
في حدث `push` لا يوجد `inputs` ⇒ القيمة `null`؛ وتعبيرات GitHub تعامل `null` و`false` كـ`0`، فتصير المقارنة `false` ⇒ **الخطوة تُتخطى بلا أي تحذير**.

النتيجة: كل التزام بعد إضافة تشغيل الدفع كان ينشر **صفر دوال**، والرحلة تقيس النسخة القديمة. لذلك كانت «الإصلاحات» تظهر بلا أثر ويُخيَّل أن العيوب تتوالد.

```yaml
# بعد
- name: نشر الدوال الست على بيئة الاختبار
  if: ${{ github.event_name == 'push' || inputs.deploy_functions }}
```

وأُضيف حاجزان يمنعان عودة الغموض:
1. **بصمة بناء**: المُجمِّع يحقن `const FUNCTION_BUILD = '<SHA>'`، وكل رد يحملها في `x-function-build` **وفي جسم الخطأ**.
2. **فحص ما بعد النشر**: الخطوة تقرأ كود كل دالة منشورة فعليًا من Management API وتقارن البصمة بـ`github.sha`، وتفشل عند أي اختلاف — فلا يمرّ نشر قديم أبدًا.

# تصميم الصلاحيات — PERMISSIONS

آخر تحديث: 2026-11-04 · المرحلة: 00 · المرجع: REQ-01، REQ-06، REQ-17، REQ-19

تصميم فقط. لا كود ولا سياسات منشورة بعد.

## 1. المبدأ الحاكم

1. **الخادم هو المرجع.** كل قراءة وكتابة وتصدير تُفحص على الخادم (RLS + Edge Function). إخفاء زر في الواجهة ليس صلاحية.
2. **الملكية تُشتق من الجلسة لا من الطلب.** لا تُقبل `teacher_id` أو `student_id` قادمة من العميل كدليل ملكية (D-018).
3. **المساعدة تتقاطع مع النطاق.** الصلاحية = فعل مسموح **و** داخل مجموعة مسموحة. لا يكفي أحدهما.
4. **السوبر أدمن قراءة فقط في الأكاديمي.** لا يوجد أي مسار كتابة أكاديمي له، ولا انتحال هوية مدرس (D-004).
5. **الافتراضي منع.** أي فعل غير مذكور صراحةً في مصفوفة المساعد غير مسموح.

## 3. كتالوج أفعال المساعد

الصلاحية تُمنح على **الفعل** + **نطاق مجموعات**. الصيغة: `<domain>.<action>`.

| المعرّف | الفعل | ملاحظات |
|---|---|---|
| `students.read` | عرض الطلاب | بيانات التواصل تُفصل في `students.contacts` |
| `students.contacts` | عرض أرقام الهاتف وولي الأمر | منفصل عمدًا: قد يُمنح العرض دون الأرقام |
| `students.write` | إضافة/تعديل بيانات طالب | لا يشمل الحذف أو الأرشفة |
| `attendance.read` | عرض الحضور | |
| `attendance.write` | تسجيل الحضور | |
| `attendance.edit` | تعديل حضور محفوظ | يسجّل قبل/بعد/سبب |
| `grades.read` | عرض الدرجات | |
| `reports.read` | عرض التقارير | |
| `reports.export` | تصدير CSV | مسجَّل ويُقيَّد بنطاق |
| `lessons.manage` | إدارة الدروس | |
| `questions.manage` | إدارة بنك الأسئلة | |
| `exams.manage` | إعداد الامتحانات | لا يشمل بدء محاولة |
| `results.publish` | نشر النتائج | |

**أفعال محجوزة للمدرس دائمًا ولا تُمنح لمساعد:** إدارة المساعدين، تغيير كلمات مرور الطلاب، تصحيح درجة بعد اعتمادها، حذف/أرشفة بيانات حساسة، تعديل مفاتيح الإجابات.

## 4. نطاق المساعد (المجموعات)

- كل منح صلاحية يحمل `scope_group_ids` (مجموعة واحدة أو أكثر).
- نطاق فارغ = لا وصول، وليس «كل المجموعات».
- القاعدة الحاسمة: **الطالب المشترك في مجموعتين** — المساعد المقيّد بمجموعة واحدة يرى فقط البيانات المرتبطة بمجموعته (حضور، درجات، ملاحظات تلك المجموعة). لا يرى المجموعة الأخرى ولا إجماليه عبر كل المجموعات.
- إجمالي الطالب عبر كل مجموعاته متاح للمدرس فقط، ما لم يمنح المساعد نطاقًا يشمل كل مجموعات الطالب.

## 5. أين تُفرض الصلاحية

| الطبقة | ما تُفرض فيه | لماذا |
|---|---|---|
| RLS | القراءات المباشرة من المتصفح (`select`/`insert`/`update` على الجداول المملوكة) | منع التسريب حتى لو عرف المستخدم معرّف صف |
| Edge Function | كل عملية حساسة: دعوة، استعادة، بدء محاولة، حفظ، تسليم، تصحيح، إغلاق وقت، تصدير، تنبيه جماعي | D-019: لا ثقة بالمتصفح |
| Constraint/Trigger | تكرار السجلات (حضور مزدوج، محاولة نشطة ثانية)، ثبات النسخة بعد التسليم | ضمان على مستوى البيانات لا التطبيق |
| الواجهة | إخفاء ما ليس مسموحًا | تجربة استخدام فقط، **ليست** أمانًا |

## 7. ما لا يُمنح أبدًا

- `service_role` key في المتصفح أو في `public/` (D-017) — عيب أمني مانع.
- سياسة RLS تعتمد على قيمة يرسلها العميل.
- صلاحية تُنفَّذ في الواجهة فقط.
- وصول سوبر أدمن للكتابة الأكاديمية ولو «للتصحيح».
- مساعد يدير مساعدين أو يوسّع نطاقه.

# الصلاحيات ورحلات الأدوار — PERMISSIONS

**الحالة:** تصميم ملزم للمرحلتين ٠٢ و٠٤ · **الأساس:** C-01…C-05 · **آخر تحديث:** 2026-11-04

## ١) المبدأ الحاكم

1. **كل شيء على الخادم**: كل قراءة وكتابة وتصدير تُفحص بـRLS أو Edge Function. إخفاء زر ليس صلاحية.
2. **الملكية تُشتق من العضوية** في قاعدة البيانات (`app.teacher_memberships`)، لا من `teacher_id` يرسله المتصفح.
3. **النطاق (Scope) جزء من الصلاحية**: فعل ممنوح بلا نطاق مجموعات = لا وصول لبيانات طالب.
4. **السوبر أدمن للقراءة الأكاديمية فقط**؛ لا كتابة على الحضور أو الدرجات أو مفاتيح الإجابة (C-04).
5. **المساعد لا يمنح نفسه** ولا يعدّل صلاحياته؛ تغيير الصلاحية يُسجَّل ويُطبّق على الطلب التالي.

## ٢) رحلات الأدوار

### أ) السوبر أدمن

```text
دخول (بمصادقة ثنائية — R-09)
  → لوحة عامة: عدد المدرسين، الحسابات النشطة، الطلاب، المحاولات، استخدام
  → دعوة مدرس (بريد/هاتف المدعو؟ لا — دعوة برابط أحادي الاستخدام) → متابعة التفعيل
  → إيقاف/تفعيل حساب مدرس → يُمنع الوصول الجديد فورًا
  → فتح ملف مدرس: بيانات الحساب + ملخص أكاديمي **للقراءة فقط**
  → إرسال تعليمات داخل المنصة (تنبيه داخلي لكل المدرسين أو لمدرس)
  → لا زر تعديل حضور/درجة/مفتاح إجابة في أي شاشة إدارية
```

**حدود صريحة:** لا «انتحال هوية» ولا تبديل سياق إلى مساحة مدرس في الإصدار الأول. أي محاولة كتابة أكاديمية من واجهة الإدارة يجب أن تُرفض على الخادم حتى لو أُرسلت يدويًا.

### ب) المدرس

```text
دخول → مساحة عمله (واحدة، حتى لو عمل في عدة أماكن)
  → الأماكن والمجموعات ← تسجيل طلاب ← توليد دعوة ربط للطالب
  → المساعدون: دعوة + منح أفعال ونطاق مجموعات
  → الحصص والحضور ← تعديل موثق
  → الدروس (نص/صور/معادلات/يوتيوب) ← إتاحة لمجموعات
  → بنك الأسئلة ← تكوين امتحان ← نشر ← متابعة المحاولات ← نشر النتائج
  → التقارير وتصدير CSV
```

### ج) المساعد (مثال: مساعد بصلاحية حضور لمجموعة واحدة)

```text
دخول → مساحة المدرس الذي منحه الصلاحية
  → يرى فقط المجموعات الممنوحة، فقط الأفعال الممنوحة
  → يسجّل حضور «مليج ٧» ✅
  → يحاول فتح طالب في «شبين ٦» ← **رفض على الخادم** (لا شاشة فقط)
  → يحاول تعديل درجة ← **مرفوض** (الفعل غير ممنوح)
  → الطالب المشترك في مجموعتين: يرى بياناته المرتبطة بمجموعته فقط، لا حضور/درجات المجموعة الأخرى
```

### د) الطالب

```text
دخول (هاتف/كود + كلمة مرور)
  → قائمة «مساحاتي»: المدرسون المرتبط بهم فقط
  → اختيار مساحة → الدروس المتاحة لمجموعاته، الحضور، درجاته هو فقط
  → قبول دعوة ربط جديدة → تصبح مساحة إضافية
  → امتحان متاح → محاولة واحدة نشطة → تسليم → نتيجة عند السماح
  → لا يرى: زملاءه، أرقامهم، مدرسًا غير مرتبط، مفتاح إجابة قبل السماح
```

## ٤) أمثلة رفض يجب أن تنجح فيها اختبارات العزل

| # | السيناريو | النتيجة المطلوبة |
|---|---|---|
| 1 | مدرس A يطلب `GET /students?id=<طالب مدرس B>` | صفر صفوف (RLS)، لا 403 يكشف الوجود |
| 2 | مساعد مقيّد بمجموعة G1 يطلب حضور طالب في G2 | صفر صفوف |
| 3 | مساعد يعدّل صلاحياته عبر استدعاء دالة | مرفوض (لا صلاحية) + حدث تدقيق |
| 4 | سوبر أدمن يرسل `PATCH` على سجل حضور | مرفوض على الخادم |
| 5 | طالب يقرأ `attempt_questions` لمحاولة زميله | صفر صفوف |
| 6 | طالب يقرأ مفتاح الإجابة قبل السماح | الحقل غير موجود في الاستجابة أصلًا |
| 7 | طالب يعدّل توقيت محاولته | مرفوض — الوقت من الخادم فقط |
| 8 | مدرس A يصدّر طلاب مدرس B | ملف فارغ / مرفوض |

## ٥) خريطة الصلاحية إلى التنفيذ

| الطبقة | ما تفعله |
|---|---|
| RLS | تقرأ الجداول: الطلاب، المجموعات، الحضور، الدروس، النتائج، التنبيهات |
| Edge Functions | الأفعال الحساسة: الدعوات، الاستعادة، بدء/حفظ/تسليم/تصحيح، التصدير، التنبيه الجماعي |
| قيود القاعدة | فرادة العضوية والحضور والمحاولة، وعدم إمكان تعديل المحاولة بعد التسليم |
| الواجهة | تُخفي ما لا يُسمح به — **تحسين تجربة فقط، وليست حماية** |

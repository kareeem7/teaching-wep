## ٢-ب) عينة القبول الواقعية (البند ١٠ من §16 في وثيقة المتطلبات)

عينة ثابتة تُبنى في بيئة الاختبار وتُستخدم في كل المراحل، ويُرفض أي «نجاح» لا يمر بها:

| العنصر | التعريف |
|---|---|
| مدرسان مستقلان | «أ. محمد» و«أ. سارة» — لا يشتركان في بيانات، ويتشابه اسم مكان لديهما («مليج ٧») عمدًا |
| أماكن متداخلة مكانيًا | مليج · شبين · ملحق — أسماء متكررة بين المساحتين مع فصل تام |
| مجموعات | لكل مدرس ٣ مجموعات، منها مجموعة واحدة بأقل من ٥ طلاب |
| طالب لدى مدرسين | «أحمد س.» مرتبط بالمدرسين معًا: ملفان أكاديميان، هوية دخول واحدة |
| طالب في مجموعتين | «منة ع.» في مجموعتين عند نفس المدرس ⇒ يُحسب مرة واحدة في الإجمالي |
| مساعد مقيّد | «كريم ف.» بصلاحية حضور + عرض طلاب على مجموعة واحدة فقط |
| طالب بلا رقم | «يوسف م.» بلا هاتف ⇒ يختبر مسار O-12 المعتمد |
| امتحان بمحاولتين | بنك ٣٠ سؤالًا، سحب ١٠، محاولتان، الاحتساب = الأعلى |
| حساب موقوف | مساعد يُوقف أثناء وجود جلسة نشطة |

**قاعدة:** إن لم تحدد العينة في المرحلة ٠٤، تُنشأ بـ`seed` اختباري وتُوثَّق في `docs/test-artifacts/`.

## ٣) اختبارات على الواجهة (خطط)

- **RTL:** لا انعكاس خاطئ للأيقونات، ترتيب القراءة صحيح، المعادلات معزولة `dir=ltr`.
- **استجابة:** ٣٦٠px، ٧٦٨px، ١٢٨٠px — بلا تمرير أفقي.
- **وصول:** تباين AA، تنقل بلوحة المفاتيح في كشف الحضور وغرفة الامتحان، تسميات ARIA عربية.
- **حالات:** فارغ/تحميل/خطأ/انقطاع لكل شاشة (مذكورة في `WIREFRAMES/`).
- **أداء حسّاس:** تحميل صفحة الامتحان < ٢.٥ ثانية على ٣G سريع (هدف، لا ضمان).

## ٦) سياسة البيانات في الاختبار

1. **لا بيانات طلاب حقيقية في بيئة التطوير أو الاختبار.**
2. بيانات مولّدة: أسماء عربية شائعة صناعية، أرقام هاتف في نطاق محجوز للاختبار.
3. أي استخدام لبيانات حقيقية يحتاج: موافقة العميل + إخفاء هوية + بيئة منفصلة + حذف بعد الاختبار.
4. نسخة الإنتاج لا تُنسخ إلى بيئة اختبار بلا تعقيم.

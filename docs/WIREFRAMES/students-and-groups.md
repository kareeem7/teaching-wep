# نموذج شاشة — الطلاب والمجموعات

المرحلة: 04 · الصفحات: `teacher/students.html`, `student-create.html`, `student-profile.html`, `groups.html`, `group-detail.html`, `locations.html`
المتطلبات: REQ-04، REQ-05، REQ-08

## الغرض

إدارة ملفات الطلاب داخل مساحة المدرس، والأماكن والمجموعات والعضويات، بلا خلط بين المساحات.

## 1. قائمة الطلاب

```
┌──────────────────────────────────────────────────────────────┐
│ الطلاب (١٢٤)                              [+ طالب جديد]      │
│ 🔎 بحث بالاسم/الكود/الهاتف   [الصف ▾][المكان ▾][المجموعة ▾]  │
├──────────────────────────────────────────────────────────────┤
│ الاسم        │ الكود  │ الصف │ المكان │ المجموعات │ الحالة   │
│ أحمد م.      │ 1042   │ 3ث  │ مليج   │ مليج ٧م   │ نشط      │
│ سارة ع.      │ 2210   │ 2ث  │ شبين   │ شبين ٦م + مليج ٩م │ نشط │
└──────────────────────────────────────────────────────────────┘
```

- البحث والفلاتر **مقيّدة بنطاق المستخدم على الخادم**، لا في الواجهة.
- ترقيم إلزامي (٢٥/٥٠ صفًا).
- عمود «المجموعات» يظهر العضويات النشطة فقط، مع رابط للتفاصيل.

## 2. إنشاء طالب

الحقول: الاسم الكامل، الصف/المرحلة، المادة، المكان، المجموعة، الهاتف (اختياري)، ولي الأمر (اختياري)، ملاحظات.

سلوك القبول:
1. حفظ الملف الأكاديمي في مساحة المدرس.
2. توليد **دعوة ربط** (رمز أحادي، بصمة مخزّنة) — الطالب يضبط كلمة مروره بنفسه.
3. لا ربط تلقائي لحساب موجود بتشابه الهاتف/الاسم (REQ-02).
4. حالة الملف تبدأ «معلّق» حتى قبول الربط، أو «نشط» حسب السياسة المعتمدة.

**تحذير في الواجهة:** إن أدخل المدرس كلمة مرور يدويًا فسيعرفها (L-06) — يُفضَّل مسار الدعوة.

## 3. ملف الطالب

```
┌ أحمد محمود — كود 1042 — 3ث ────────────────────────────┐
│ [بيانات] [المجموعات] [الحضور] [النتائج] [الملاحظات] [السجل]│
├────────────────────────────────────────────────────────┤
│ الهاتف: ████  (يظهر حسب صلاحية students.contacts)      │
│ ولي الأمر: ████                                        │
│ الحالة: نشط  [تعليق] [أرشفة]  → بسبب إلزامي            │
└────────────────────────────────────────────────────────┘
```

- «الحضور» يفتح `attendance-history.html` لنفس الطالب.
- «النتائج» يعرض النسب المئوية مع عدد الامتحانات وطريقة الاحتساب.
- «السجل» يعرض تغييرات مختصرة لمن يملك الصلاحية.
- **لا تُعرض** بيانات زملاء أو أرقامهم.

## 4. المجموعات

- بطاقة مجموعة: الاسم («مليج — الساعة ٧»)، المادة، الصف، المكان، الأيام والميعاد، العدد/السعة، الحالة.
- `group-detail.html`: الأعضاء، العضويات السابقة، الحصص.
- نقل طالب بين مجموعات يُغلق العضوية القديمة بـ`left_at` ويحفظ التاريخ (REQ-04).

## 4-ب. إدارة المساعدين (الشاشة المطلوبة في المهمة ٥)

> لا يوجد ملف نموذج مستقل باسم `assistants.md` في قائمة المرحلة ٠٠ الملزمة، فمكان هذا النموذج هنا. الصفحات الفعلية: `teacher/assistants.html` و`teacher/assistant-permissions.html` (المرحلة ٠٤).

### قائمة المساعدين

```
┌──────────────────────────────────────────────────┐
│ المساعدون (٣)                        [+ مساعد]   │
├──────────────────────────────────────────────────┤
│ الاسم     │ المجموعات المسموحة │ الأفعال │ الحالة │
│ محمد ع.   │ مليج ٧م             │ ٣ أفعال │ نشط    │
│ هدى س.    │ شبين ٦م + مليج ٩م   │ ٦ أفعال │ نشط    │
└──────────────────────────────────────────────────┘
```

### شاشة الصلاحيات (فعل × نطاق)

```
┌ صلاحيات: محمد ع. ────────────────────────────────┐
│ المجموعات المسموحة:                              │
│   [✓] مليج — ٧م      [ ] شبين — ٦م               │
│                                                  │
│ الأفعال:                                         │
│   [✓] students.read       [ ] students.write     │
│   [✓] students.contacts   [ ] attendance.edit    │
│   [✓] attendance.read     [ ] reports.export     │
│   [✓] attendance.write    [ ] lessons.manage     │
│   [ ] grades.read         [ ] questions.manage   │
│   [ ] exams.manage        [ ] results.publish    │
│                                                  │
│ محجوز للمدرس ولا يُمنح: إدارة المساعدين،         │
│ تغيير كلمات مرور الطلاب، تصحيح درجة معتمدة.      │
│                          [إلغاء] [حفظ الصلاحيات] │
└──────────────────────────────────────────────────┘
```

### قواعد

1. **الفعل والنطاق معًا:** صلاحية بلا مجموعة = لا وصول (نطاق فارغ ليس «كل المجموعات»).
2. المساعد لا يصل لهذه الشاشة إطلاقًا — لا عرضًا ولا طلبًا.
3. أي تغيير يُسجَّل ويُطبَّق على الطلب التالي فورًا، لا بعد إعادة دخول.
4. تعطيل المساعد يمنع كل أفعاله فورًا.
5. لا يستطيع المساعد منح نفسه صلاحية ولو عدّل الطلب يدويًا.

### معايير القبول

- T-06-01..06 في `REQUIREMENTS_TRACEABILITY.md`.
- مساعد بنطاق واحد لا يرى طالب المجموعة الأخرى ولو كان الطالب نفسه مشتركًا.

## 5. الأماكن

- قائمة بسيطة: «مليج»، «شبين» — **بدون أي مشاركة** مع مدرس آخر يشبهه في الاسم.
- حذف مكان مستخدم ممنوع؛ أرشفة فقط.

## الحالات

| الحالة | العرض |
|---|---|
| لا طلاب | «أضف أول طالب» + شرح مسار الدعوة |
| بحث بلا نتائج | «لا نتائج» + زر مسح الفلاتر |
| رقم هاتف مكرر | تحذير للمراجعة، **لا دمج تلقائي** (REQ-05) |
| صلاحية غير كافية | الحقل مخفي/معطّل + رفض على الخادم إن حاول |

## معايير القبول

1. إجمالي الطلاب = أشخاص فريدون، لا مجموع عضويات (REQ-04).
2. المساعد المقيّد لا يصل لطالب خارج مجموعته حتى بمعرّفه (ISO-03).
3. نقل طالب لا يغيّر تاريخ العضوية القديمة.
4. لا دمج تلقائي بالهاتف.

# نموذج شاشة — كشف الحضور

المرحلة: 05 · الصفحة: `public/pages/teacher/attendance-sheet.html` · السكربت: `public/assets/js/teacher/attendance.js`
المتطلبات: REQ-07، REQ-18

## الغرض

رصد حضور حصة واحدة لمجموعة، جماعيًا وفرديًا، على الموبايل أولًا، بمنع التكرار وحفظ التعديل بسبب.

## التخطيط (موبايل أولًا)

```
┌──────────────────────────────────────┐
│ ← مليج — الساعة ٧ · الأحد ٣ نوفمبر  │
│ الحصة: [جديدة ▾]       ٢٤ طالبًا     │
├──────────────────────────────────────┤
│ [حاضر الجميع]  [مسح الكل]            │
├──────────────────────────────────────┤
│ أحمد م.                    [ح][غ][ت][ع] │
│ سارة ع.                    [ح][غ][ت][ع] │
│ محمود س.                   [ح][غ][ت][ع] │
│ ...                                   │
├──────────────────────────────────────┤
│ ملخص: حاضر ١٨ · غائب ٢ · متأخر ١    │
│ لم يُرصد: ٣                          │
│              [ حفظ الحضور ]           │
└──────────────────────────────────────┘
```

## قواعد التفاعل

1. **«لم يُرصد» ليست غيابًا.** الطالب الذي لا حالة له يظهر بادج محايد بنص «لم يُرصد»، ولا يُحتسب في أي نسبة.
2. التسجيل الجماعي يملأ الحالة **قابلة للتعديل** قبل الحفظ.
3. الحفظ الذرّي عبر `attendance-save` (Edge Function) بمعامل `session_id`، مع `unique(session_id, student_profile_id)`.
4. إعادة الإرسال (شبكة بطيئة/ضغط مزدوج) لا تُنشئ صفوفًا مكررة.
5. تعديل حالة محفوظة سابقًا يفتح نافذة **سبب إلزامي**، ويُسجَّل قبل/بعد/الفاعل.
6. مؤشر حفظ صادق: «تم الحفظ» يعني استجابة خادم ناجحة، لا حفظًا محليًا.

## الحالات الأربع

| الحالة | الاختصار | ما يُحتسب في نسبة الحضور (D-106) |
|---|---|---|
| حاضر | ح | نعم (بسط) |
| متأخر | ت | نعم (بسط) — قابل للتغيير بقرار العميل |
| غائب بعذر | ع | لا بسط، ويبقى في المقام |
| غائب | غ | لا بسط، ويبقى في المقام |

> بانتظار اعتماد العميل لسياسة الاحتساب (P-06 / D-106). الشاشة تعرض ملخصًا مطابقًا للسياسة المعتمدة فقط.

## الصلاحيات

- `attendance.write` للرصد، `attendance.edit` للتعديل بعد الحفظ (فعلان منفصلان).
- المساعد المقيّد يرى طلاب مجموعته فقط؛ لا يظهر أي طالب خارج النطاق.
- صلاحية الرصد لا تعني صلاحية التعديل.

## الحالات الفارغة والخطأ

| الحالة | العرض |
|---|---|
| مجموعة بلا طلاب | «لا طلاب في هذه المجموعة» |
| حصة محفوظة | تظهر القيم مع قفل افتراضي + مسار «تعديل بسبب» |
| انقطاع اتصال | شريط «غير متصل — لن يُحفظ» وتعطيل الزر |
| رفض خادم | رسالة محددة + عدم ادعاء نجاح |

## RTL وإتاحة

- أزرار الحالة كبيرة (≥ ٤٤×٤٤px) للمس.
- كل حالة لها **نص** لا لون فقط.
- بلا تمرير أفقي على ٣٦٠px.
- دعم لوحة المفاتيح: Tab للتنقل، ١–٤ لتعيين الحالة، Enter للحفظ.

## معايير القبول

1. لا ازدواج سجل لنفس الطالب في نفس الحصة (ENG/قيد قاعدة بيانات).
2. ملخص الشاشة = الأرقام المخزنة فعليًا.
3. التعديل ينتج سجلًا يحمل قبل/بعد/سببًا.
4. المساعد بلا `attendance.write` يُرفض على الخادم لا في الواجهة.
